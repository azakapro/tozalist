# Webhooks

TozaList can notify your systems when a batch finishes. Register an HTTPS
endpoint, store the signing secret we show you once, and check the signature
on every request before trusting it.

## Events

| Event             | Sent when                                                     |
| ----------------- | ------------------------------------------------------------- |
| `batch.completed` | A batch finished processing and its results are ready.        |
| `batch.failed`    | A batch could not be processed; its reservation was refunded. |

## Delivery format

Every delivery is an HTTP `POST` with a JSON body:

```json
{
  "event": "batch.completed",
  "data": {
    "batch_id": "3f2a4b1c-9d8e-4f00-8a11-000000000000",
    "status": "done",
    "total_rows": 1000,
    "verdict_counts": { "valid": 800, "invalid": 120, "risky": 50, "unknown": 30 }
  },
  "timestamp": "2026-08-24T12:00:00.000Z",
  "delivery_id": "0b6a1f9e-1111-4222-8333-444455556666"
}
```

Headers:

| Header          | Meaning                                                                       |
| --------------- | ----------------------------------------------------------------------------- |
| `X-Signature`   | Hex HMAC-SHA256 of the **raw request body**, keyed with your endpoint secret. |
| `X-Timestamp`   | The same ISO 8601 timestamp as in the body.                                   |
| `X-Delivery-Id` | Stable ID for this delivery; retries reuse it. Use it to deduplicate.         |
| `X-Event-Type`  | The event name.                                                               |

Behavior:

- Deliveries time out after 5 seconds. Any `2xx` response counts as delivered.
- Redirects are **never** followed.
- Failed deliveries retry after 1 minute, 5 minutes, 30 minutes, 2 hours, and
  6 hours; after the sixth attempt the delivery is marked failed.
- Each attempt re-signs a fresh envelope, so check the timestamp, not just
  the signature.

## Checking signatures

Always compute the HMAC over the **exact raw bytes** of the body (before any
JSON parsing), compare it in constant time, and reject stale timestamps to
prevent replay.

### Node.js

```js
import { createHmac, timingSafeEqual } from 'node:crypto'

const TOLERANCE_MS = 5 * 60 * 1000 // 5 minutes

/**
 * @param {string} secret    your whsec_... endpoint secret
 * @param {Buffer} rawBody   the unparsed request body bytes
 * @param {string} signature the X-Signature header
 * @param {string} timestamp the X-Timestamp header
 */
export function verifyWebhook(secret, rawBody, signature, timestamp) {
  const age = Math.abs(Date.now() - Date.parse(timestamp))
  if (!Number.isFinite(age) || age > TOLERANCE_MS) {
    return false // stale or unparseable: possible replay
  }

  const expected = createHmac('sha256', secret).update(rawBody).digest()
  const received = Buffer.from(signature, 'hex')
  if (received.length !== expected.length) return false
  return timingSafeEqual(expected, received) // constant-time comparison
}
```

### Python

```python
import hashlib
import hmac
from datetime import datetime, timezone

TOLERANCE_SECONDS = 5 * 60  # 5 minutes


def verify_webhook(secret: str, raw_body: bytes, signature: str, timestamp: str) -> bool:
    try:
        sent_at = datetime.fromisoformat(timestamp.replace("Z", "+00:00"))
    except ValueError:
        return False
    age = abs((datetime.now(timezone.utc) - sent_at).total_seconds())
    if age > TOLERANCE_SECONDS:
        return False  # stale or future-dated: possible replay

    expected = hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)  # constant-time comparison
```

Reject the request (HTTP 401) whenever the signature check fails. Never log
the secret, and never compare signatures with `==` — use the constant-time
helpers shown above.

## Registering endpoints

```
POST   /v1/webhooks          {"url": "https://example.com/hooks", "events": ["batch.completed"]}
GET    /v1/webhooks
DELETE /v1/webhooks/{id}
```

Rules: HTTPS only; hostnames must resolve to public addresses (private and
reserved ranges are rejected, at registration and again at every delivery);
the secret is returned exactly once at registration.
